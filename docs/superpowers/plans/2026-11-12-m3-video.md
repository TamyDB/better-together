# M3 Vídeo: Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O convidado vê a tela do Host ao vivo (720p, até 30 fps) no viewer, com os bichinhos desenhados localmente por cima e alinhados à imagem. A overlay do Host fica fora da captura (`WDA_EXCLUDEFROMCAPTURE`), então os bichinhos nunca aparecem duplicados. O Host pode pausar, retomar e trocar a tela compartilhada sem derrubar ninguém.

**Architecture:** A captura e o vídeo vivem só no TS (WebView2): o Host chama `getDisplayMedia` uma vez e põe a mesma `MediaStreamTrack` num transceiver `sendonly` de cada `PeerLink` (um encode por convidado, como a spec prevê). Pausar ou trocar a tela é `replaceTrack`, sem renegociar. O convidado recebe a track em `ontrack` e a mostra num `<video>` posicionado no mesmo `fitRect` que o canvas usa, então as coordenadas normalizadas da `sim` continuam valendo. O Rust só aplica a afinidade de captura na overlay e informa se deu certo; nenhuma mensagem de jogo muda.

**Tech Stack:** o que já existe no M2. No Rust, a feature `Win32_UI_WindowsAndMessaging` do `windows` 0.58 (já presente) cobre `SetWindowDisplayAffinity`. Sem dependências novas no TS.

**Spec:** `docs/superpowers/specs/2026-11-05-desktop-multiplayer-design.md`
**Pendências herdadas:** `docs/superpowers/plans/2026-11-06-m2-pendencias.md` (seção M3 entra inteira; dois itens "Adiados" entram na Task 7)

## Global Constraints

- `PROTOCOL_VERSION` continua `1` e o `dm-protocol` não muda: vídeo não passa pelo Rust nem pelos DataChannels.
- O Host é sempre o *offerer*. O convidado nunca envia oferta e nunca envia mídia. O Host só aceita `answer`; o convidado só aceita `offer` (Task 1).
- Uma única captura no Host, compartilhada por todos os `PeerLink`. Trocar ou pausar o vídeo é `RTCRtpSender.replaceTrack`, nunca uma nova oferta.
- Vídeo: `getDisplayMedia({ video: { displaySurface: "monitor", width: { max: 1280 }, height: { max: 720 }, frameRate: { max: 30 } }, audio: false })`, `track.contentHint = "detail"` (texto legível vale mais que fluidez), encoding com `maxBitrate: 2_500_000` e `maxFramerate: 30` por convidado (cerca de 7,5 Mbps de upload com 3 convidados).
- `getDisplayMedia` exige gesto do usuário: é chamado de forma síncrona dentro do `onclick` ("Criar sala", "Compartilhar tela", "Trocar tela"), antes de qualquer `await`.
- Recusar o seletor de tela não impede a sala: ela abre sem vídeo e o painel oferece "Compartilhar tela".
- Toda track capturada é parada (`track.stop()`) ao encerrar a sessão, ao trocar de tela e ao recarregar; o indicador de compartilhamento do Chromium nunca fica aceso depois do "Encerrar".
- Coordenadas: o `<video>` usa `object-fit: fill` dentro do `fitRect(aspect do Host)`, o mesmo retângulo do canvas. Se a tela capturada não for o monitor primário (outra tela, janela ou proporção diferente), o painel avisa o Host; o convidado não é bloqueado.
- `WDA_EXCLUDEFROMCAPTURE` fica atrás de `#[cfg(windows)]`. Falhou (Windows anterior ao 10 2004)? A sessão segue e o painel avisa que os bichinhos vão aparecer duplicados no vídeo.
- O TS continua sem regra de jogo. Textos da UI em português. Workspace compila e testa no Linux.

## Review Focus

1. **Convidado malicioso renegociando:** um convidado manda uma `offer` (para empurrar mídia ou trocar os canais), uma `answer` com `m=audio`, ou um SDP de 1 MB. O Host ignora tudo isso e o par continua como estava. Testes na Task 1.
2. **Trocar ou pausar a tela com convidados entrando e saindo:** a track atual vale para todos os peers vivos e para quem entrar depois; peer fechado não recebe `replaceTrack`; a track antiga é parada uma única vez. Testes na Task 3.
3. **Fim de sessão:** "Encerrar", "Voltar", o Host fechando o seletor do Chromium ("Parar de compartilhar") e reload. Em todos os casos, nenhuma track fica viva e nenhum `invoke` sai depois do `stop()`. Testes nas Tasks 3 e 6.
4. **Alinhamento:** os bichinhos ficam sobre o mesmo ponto da imagem em 16:9, 21:9 e 16:10, com o viewer redimensionado. Teste do `fitRect` (M2) e checagem manual na Task 8.
5. **Overlay fora do vídeo:** a afinidade é aplicada antes do `show()`; a falha é reportada, nunca engolida. Teste Windows na Task 4.
